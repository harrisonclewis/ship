# Server setup

1. Add the server to `ship.yaml` (see [Configuration](configuration.md)) or with `a` in the [TUI](tui.md). Set `host` to `root@<ip>` for the very first run, and `identity_file` to the private key that logs in to it, unless your ssh config or agent already does. `ship setup` copies root's authorised keys to the admin user, so the same key works after `lock-ssh`. Point the app domains' A/AAAA records at the server.
2. Prepare the server:

   ```sh
   ship prod setup
   ```

3. Check the admin login, then change `host` to `ops@<ip>` and lock SSH down:

   ```sh
   ssh ops@<ip> sudo true
   ship prod lock-ssh
   ```

   `lock-ssh` disables root and password logins and allows only `admin_user` and `deploy`.

4. Deploy the proxy and apps:

   ```sh
   ship prod proxy update
   ship prod deploy all
   ```

Caddy obtains certificates once DNS resolves; it retries in the background.

Examples use a server named `prod`. With only one server in `ship.yaml` you can leave the name out: `ship setup`.

## After upgrading ship

Maintenance pages need a mount in the Caddy container that older setups don't have. Run this once per server; until then, deploys of apps with maintenance turned on stop early and say so:

```sh
ship prod setup
ship prod proxy update
```

## What setup does

- Installs packages, including Docker from Docker's repository.
- Creates `admin_user` (`ops` by default) with root's SSH keys and passwordless sudo, the `deploy` user, and app users for configured `uid`s.
- Adds ufw rules for SSH, 80 and 443. Existing rules are kept.
- Turns on unattended security updates, adds 2 GB swap if the server has none, and caps Docker logs.
- Creates the `web` network, `/opt/proxy` (including the `maintenance/` flag folder Caddy reads), `/opt/apps` and the nightly backup timer.

It is safe to re-run and does not overwrite existing swap, ufw rules or users.

## Server layout

| Path | What |
|---|---|
| `/usr/local/sbin/ship-agent` | the agent, installed and updated by the CLI ([details](updates.md#the-server-agent)) |
| `/opt/proxy/` | Caddy compose file, generated Caddyfile and pinned image |
| `/opt/apps/<name>/` | the app's compose file and state, see below |
| `/var/backups/ship/<name>/` | archives, root 0600 in 0700 directories |
| `web` network | external Docker network `172.30.0.0/24`; only Caddy publishes ports |

Each `/opt/apps/<name>/` holds:

| File | What |
|---|---|
| `compose.yaml` | uploaded from `apps/<name>/compose.yaml` |
| `Dockerfile` | release apps only |
| `.ship-meta` | app metadata |
| `.ship-env` | uploaded non-secret values from `ship.yaml` |
| `.ship-deploy.sh` | the app's deploy commands, if any |
| `.ship.env` | generated by the agent from `IMAGE` and `.ship-env` |
| `.env` | secrets, root 0600, edited with `ship <server> env edit` |
| `.ship-state` | current and previous image |
